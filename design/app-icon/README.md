# App icon — visionOS layered icon

Built by `build_icon.py` (pure Python + Pillow) from the six AI-recreated source components in
`source/` (plus the concept board `source/REFERENCE_Concept_Board.png` and the original brief,
`source/CLAUDE_CODE_PROMPT.md`). The components were generated by Mo with ChatGPT image generation on
4 October 2026. Every
geometric choice is measured from the layers at run time and written to `build_icon_measurements.json`.
Re-run: `python3 design/app-icon/build_icon.py`.

Installed (2026-10-05, **not committed** — the icon is checked on the headset first):

## Background

- `03_night_environment` is a solid rectangle at x 107–918, y 118–907 (alpha ≥ 248 on ≥ 97 % of every
  row and column; 762 softer pixels inside, star cores and glow). Everything outside it is a faded card
  edge and is discarded.
- Cropped to that rectangle and scaled **uniformly by 1.2962** (the cover scale: 790 px tall → 1024).
- Then shifted **(−63, +148)** so the crescent sits fully inside the arch opening. The check is row by
  row: the crescent's bright extent on each row (glow-dilated by ~8 px) against the opening's span on
  that row, with a 10 px margin. A bounding-box check cannot pass, because the crescent's thin horn sits
  inside the pointed arch where a box's corners do not.
- **Two bands are exposed by that shift and are filled by mirroring the image's own edge**, not by
  feathering into navy (the review found a feathered edge still reads): a 148 px band at the top
  (mirrored sky, stars) and a 34 px strip at the right (mirrored sky/lake). This is the one departure
  from "scale to cover, then shift": at the cover scale the crescent is in the right half of the opening
  and cannot clear the arch's inner right face without moving further left than the cover width allows.
  A larger scale reduces the bands (1.40× → 106/14 px) at the cost of cropping the mountains and lake;
  the cover scale was kept. `qa/background_crescent_in_arch.png` marks both bands in magenta.
- Horizon (mountain ridge) lands at y 716, between the pillar tops (484) and the arch base (778).
- Every Background pixel is alpha 255.

## Page text

The book's pages carried AI-generated imitation Arabic and ayah-marker-like diamonds. This app never
shows generated Quranic text, so everything inside each page's text block was removed with a strong
horizontal smear, gold borders kept.

- **The two text blocks are fixed, hand-measured outlines** (Mo's review, 5 Oct 2026, measured on the
  source at 5×), in 1024 px Foreground coordinates, filled with no feathering. They are in
  `build_icon.py` (`LEFT_BLOCK`, `RIGHT_BLOCK`) and in `build_icon_measurements.json`.
- **Why not detected:** automatic detection was tried through several rounds (a stroke convex hull, a
  row-by-row walk toward the gutter, extrusion to the bottom border, frame rules by colour and by shape,
  a leftover map). Each version either stopped short of the gutter, leaving word endings, or ran over a
  border into the margin, and the checks written for one failure did not cover the next. A fixed
  outline is checked once, by eye, and does not move; that code is gone.
- The smear is a **61 px masked horizontal mean**: sum(pixel × mask) / sum(mask) over the window, so the
  frame and the page margin never bleed in; then a 1.2 px soften; both composited back through the same
  mask. Solid alpha (≥ 248) is set to 255 as before.
- Residual local contrast inside the blocks (|pixel − 3 px blur|): mean 20.0 → **2.7**, p99 87 → 15,
  max 133 → 25.

## Alpha

Solid pixels in the sources are alpha 252–253. In Middle and Foreground every alpha ≥ 248 is set to
255; softer edge alpha (1–247) is left as is: Middle 169,013 opaque / 17,058 soft; Foreground 67,742 /
3,419. No pixel in either lies in 248–254 any more. No checkerboard: the transparent layers have no
opaque neutral-grey pixels.
